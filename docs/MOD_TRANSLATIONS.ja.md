# 他の Mod のテキストの翻訳

[English](MOD_TRANSLATIONS.md)

作成日: 2026-09-17。**設計のみで、まだ実装していません。** きっかけは [Issue #28](https://github.com/TomXV/dragnwash-localization/issues/28)（新しい仕組み・UI・会話を足す Mod のテキストは翻訳できるか）。

## 結論

- 他の Mod の訳は、**その Mod 自身が同梱する**。置き場所は `BepInEx/plugins/<その Mod>/Translations/<locale>/strings.csv` で、形式はこの Mod の `strings.csv` と同じ。
- Localization は、自分の言語パックを読んだ後に、読み込まれている Mod のパックも読む。**Mod のパックはゲーム本体の行を上書きできない**。食い違いは「競合」として記録する。
- このリポジトリは、他の Mod の訳を持たない。Mod が更新されるたびにこちらが追いかけることになり、「全部を抱えない」に反するため。
- **β版の実験的機能として入れ、既定はオフ**。他の Mod との組み合わせは未知の領域なので、使う人がそれを承知の上でオンにする（[下](#β版の実験的機能として)）。
- **自動翻訳（機械翻訳）は組み込まない**。理由は[下](#自動翻訳を組み込まない理由)に書いた。Mod の作者や翻訳者が、好きな方法で作った訳を「仮翻訳」として同梱するのは自由。

## 今の仕組みでどこまで動くか（コードで確認）

| 問い | 今の答え |
|---|---|
| 他の Mod の UI テキストは訳せるか | **TextMeshPro で出していて、行があれば訳せる**。照合は「表示される英文のハッシュ → 訳」の 1 つの辞書（`TranslationStore`）で、フレームワークの Text ライブラリが TMP の `text` の代入・`SetText(string)`・表示の有効化のたびに引く。誰が出したテキストかは見ていない。**古い uGUI の `Text`、IMGUI（`GUI.Label` など）で自分で描く文字、`SetText` の書式つきの形は対象外** |
| 自動で見つかるか | 上と同じ TMP の経路なら、未翻訳の文字列が `_discovered/strings.csv` に自動で記録され、F7 の書き出しにも入る。会話は、F6 が**読み込まれている YarnProject をすべて**書き出すので、Mod が自前の YarnProject を使っていれば入る。Yarn を通さずに TMP へ直接入れる会話は、UI テキストとして拾われる |
| Mod が英語を変えたら | ハッシュが変わり、その行は英語に戻る。台詞 ID（`line:` の行）は Yarn の行 ID が同じなら残る。ゲーム本体向けの「近い英文から探し直す」仕組み（`LineResolution`）は、ゲームの台本だけが対象 |
| クラッシュするか | 照合は辞書を引くだけで、原理的には起きにくい。**実物の Mod ではまだ試していない** |
| 足りないもの | 訳の置き場所が、この Mod の `Translations/` しかない。他の Mod の行を足すには、このリポジトリの `strings.csv` に入れるしかない |

## β版の実験的機能として

他の Mod のテキストがどう表示されるかは、その Mod ごとに違い、こちらで全部を試すことはしない。なので、この機能は**β版の実験的機能**として入れ、使う人が承知の上でオンにする。

- 設定：**Options → Mods → Drag'n Wash Localization → Settings** の `[Experimental] Translations from other mods`。**既定はオフ**。オフの間は、他の Mod のフォルダーを一切読まない。
- 設定の説明文：「β版・実験的機能。ほかの Mod が同梱した翻訳を読み込みます。Mod との組み合わせは未確認で、表示が崩れたり、訳が合わなかったりすることがあります。問題があればオフにしてください。」
- オンにしたときは、ログに警告を 1 回出し、どの Mod のパックを読んだかを並べる。
- F1 → Translation と About にも「実験的」と出す。
- リリースノートと README では「β版・実験的機能」の見出しの下に書く。
- 不具合の報告は受けるが、特定の Mod との組み合わせを保証はしない。Mod の作者に頼まれたときだけ、その Mod で試す（[確認の計画](#確認の計画)）。
- 仕組みが固まり、試した Mod が増えたら、実験的の表示を外すかを改めて決める。

## 置き場所と形式

```
BepInEx/plugins/
  DragNWashLocalization/Translations/ko/strings.csv    ← ゲーム本体の訳（このリポジトリ）
  SomeMod/SomeMod.dll
  SomeMod/Translations/ko/strings.csv                  ← SomeMod のテキストの訳（SomeMod が同梱）
  SomeMod/Translations/ja/strings.csv
```

- 列は同じ：`key,section,node,order,speaker,translation`（短い `key,speaker,translation` と `key,translation` も可）。`key` は英文の SHA-256 の先頭 16 桁で、`tools/hash-strings.ps1 -Path <ファイル>` でそのまま作れる。
- `line:<id>` の行も使える。
- ロケールのフォルダー名は、この Mod の `Translations/` にあるものと同じにする（`ko`、`zh-Hans` など）。この Mod にない言語は選べないので、その言語のフォルダーだけあっても読まれない。
- `name.txt` は要らない（言語の表示名はこの Mod が持つ）。
- Mod 自身の英文を `source_en` 列に残したファイルも読める。この Mod のリポジトリが守っている「ゲームの英文を配らない」は、ゲームの台本についての約束で、Mod の作者が自分で書いた英文は作者のもの。ただし**ゲーム本体の英文を含めてはいけない**ことは、作者向けの説明に明記する。

## どのフォルダーを読むか

- BepInEx が読み込んだプラグイン（`Chainloader.PluginInfos`）の DLL があるフォルダーだけ。任意のフォルダーは探さない。
- この Mod 自身のフォルダーは除く。
- 1 つのフォルダーに複数のプラグインがあっても、読むのは 1 回。
- 読むのは起動時と、言語を切り替えたとき。

## 読む順と優先

1. この Mod の言語パック（ゲーム本体の訳）
2. 他の Mod のパック。GUID の順（毎回同じ順になるように）
3. 翻訳者の作業用コピー（`_discovered/<locale>.working.csv`、開発者ツールがオンのときだけ）。今と同じく、すべてに勝つ

規則：

- **Mod のパックの行は、1 の行を置き換えない。** 同じキーで訳が違えば、1 を使い、競合として記録する（訳が同じなら何もしない）。
- 2 どうしで同じキーの訳が違えば、先に読んだ Mod の訳を使い、競合として記録する。
- 競合はログに出し、F1 → Translation に一覧を出す。Mods 画面にも、関わった Mod ごとにお知らせとして出す（「Drag'n Wash Localization と訳が違う行が 3 つあります」）。そのために、フレームワークに Mod ごとのお知らせ欄を足す（[決めたこと](#決めたこと)）。

## 失敗の閉じ込め

- 読めないファイル（壊れた CSV、読み取りエラー、大きすぎるファイル。上限はたとえば 5 MB）は、**その Mod のそのファイルだけ**読まずに、理由をログに 1 回出す。ほかの Mod とゲーム本体の訳には影響しない。
- 1 つの Mod から読む行数にも上限を設ける（ゲーム本体の行数の数倍程度）。
- 読み込みはすべて起動時と言語切り替えのときだけで、表示のたびの処理は今と変わらない（辞書を引くだけ）。

## 翻訳者向けのツール

開発者ツールがオンのときだけ（今と同じ）。

- **F1 → Translation**：読み込んだ Mod のパックを、Mod 名・行数・競合の数で一覧にする。
- **ホットリロード**：Mod のパックも監視し、保存すると反映する。
- **書き出し**：
  - 会話（F6）は YarnProject ごとに分かれているので、ゲーム本体以外の YarnProject は `# ===== Mod: <プロジェクト名> =====` の見出しで分ける。
  - UI テキストは、`_discovered/strings.csv` と F7 の書き出しに `mod` 列を足し、その文字を出したプラグインを入れる。未翻訳の文字を初めて記録するときに調べる（[決めたこと](#決めたこと)）。空欄は、ゲーム本体か、判別できなかったもの。
- **Hash for commit** は、この Mod のパック用のまま。Mod のパックは `tools/hash-strings.ps1 -Path` で作る。台本の順に並べる機能はゲーム本体の台本しか知らないので、Mod の行は末尾にまとまる。

## Mod の作者向けの手順（案）

1. 自分の Mod のテキストを英語で、TextMeshPro の `text` か `SetText(string)` で出す。それだけで翻訳の対象になる（IMGUI や古い uGUI の `Text` は対象外）。
2. 翻訳者に、開発者ツールをオンにして F7（UI）・F6（会話）で書き出してもらい、自分の Mod の行（UI は `mod` 列、会話は `Mod:` の見出し）を選んで `translation` を埋めてもらう。
   会話は台詞 ID（`line:<id>` の行）で書くのがおすすめ。英文を直しても訳が残る。英文で引く行は、英文を直すと英語に戻る。
3. `tools/hash-strings.ps1 -Path` でハッシュ化し、`Translations/<locale>/strings.csv` として Mod と一緒に配る。
4. 機械翻訳などで作った訳は、ファイルの先頭のコメントに `Provisional` と書く（この Mod の仮翻訳パックと同じ）。
5. クレジットは、その Mod のもの。

## 自動翻訳を組み込まない理由

- **通信**：フレームワークは「更新の確認のほかは何も送らない」と説明している。実行時の機械翻訳は、プレイ中のテキストを外部に送ることになる。
- **鍵と費用**：誰の API キーで、誰が払うのかが決まらない。この Mod が鍵を扱うことはしない。
- **内容**：Mod には成人向けの内容もあり、翻訳サービスの利用規約に触れうる。
- **品質と責任**：誤訳が、この Mod の名前で表示される。
- **範囲**：「全部を抱えない」。訳を作る手段は、Mod の作者と翻訳者が選べばよい。

## フレームワークとの分担

最初は Localization の中で、フォルダーの置き方の約束事として作る。フレームワークに API は足さない。別の翻訳 Mod が出てきて、同じ約束事を共有したくなったら、フォルダーの発見と競合の記録をフレームワークの Text ライブラリに移す。

## 決めたこと

2026-09-17 に決定。

- **競合は Mods 画面にも出す。** 先にフレームワークに小さな「Mod ごとのお知らせ欄」を足す（フレームワークのロードマップにある項目。`GameHooks.Unavailable` は「機能が使えない」の意味なので流用しない）。そのうえで Localization が、競合に関わった Mod の下にお知らせを出す。お知らせ欄のない古いフレームワークでは、ログと F1 にだけ出す。
- **UI テキストがどの Mod のものかは、記録するときだけ調べる。** 開発者ツールがオンで、未翻訳の文字を初めて記録するときに、呼び出し履歴を 1 回たどって最初のプラグインのアセンブリを探し（フレームワークの接続の見張りと同じやり方）、その Mod を `mod` 列に入れる。表示の処理は遅くならず、開発者ツールがオフなら何も調べない。
- **Mod の台詞に `LineResolution` は効かせない。** Mod ごとの台本の順序データが要るため。代わりに Mod の台詞は台詞 ID で書いてもらう（`line:<id>` の行は英文が変わっても残る）。作者向けの手順にそう書く。英文で引く行は、英文が変わると英語に戻る。
- **この Mod にない言語は読まない。** 言語の一覧・表示名・フォントはこの Mod が持つ。そういう言語のフォルダーは、ログに 1 行出して読み飛ばす。言語を増やすときは、先にこのリポジトリにパックを足す。

## 確認の計画

- 他の Mod をこちらから進んで試すことはしない。Mod の作者から「自分の Mod で翻訳が効くか確かめてほしい」と頼まれたときに、その Mod で試す。見るのは、UI テキストが `_discovered/strings.csv` に出るか、会話が F6 で出るか、訳の行を足すと表示が変わるか、クラッシュしないか。
- 試した結果は、この設計の「今の答え」の表に反映する。
- 実装は `experimental/` ブランチで。テスト用に、テキストを出すだけの小さな Mod をこちらで作る。

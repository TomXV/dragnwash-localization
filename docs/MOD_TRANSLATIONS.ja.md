# 他の Mod のテキストの翻訳

[English](MOD_TRANSLATIONS.md)

作成日: 2026-09-17。
**2026-09-19 に `experimental/mod-translations` ブランチで実装（β版・実験的、既定はオフ）。**
**2026-09-19 に、テスト用の小さな Mod（自前のラベル、競合する行とこの Mod にない言語を含むパック）でゲームで確認しました。**
**Mods 画面へのお知らせは、フレームワークのお知らせ欄ができてから。**

きっかけは [Issue #28](https://github.com/TomXV/dragnwash-localization/issues/28)
（新しい仕組み・UI・会話を足すModのテキストは翻訳できるか）。

## 結論

- 他のModの訳は、**その Mod 自身が同梱する**。
  置き場所は `BepInEx/plugins/<その Mod>/Translations/<locale>/strings.csv` で、形式はこのModの `strings.csv` と同じ。
- Localizationは、自分の言語パックを読んだ後に、読み込まれているModのパックも読む。
  **Mod のパックはゲーム本体の行を上書きできない**。
  食い違いは「競合」として記録する。
- このリポジトリは、他のModの訳を持たない。
  Modが更新されるたびにこちらが追いかけることになり、「全部を抱えない」に反するため。
- **β版の実験的機能として入れ、既定はオフ**。
  他のModとの組み合わせは未知の領域なので、使う人がそれを承知の上でオンにする（[β版の実験的機能として](#β版の実験的機能として)）。
- **自動翻訳（機械翻訳）は組み込まない**。
  理由は[自動翻訳を組み込まない理由](#自動翻訳を組み込まない理由)に書いた。
  Modの作者や翻訳者が、好きな方法で作った訳を「仮翻訳」として同梱するのは自由。

## 今の仕組みでどこまで動くか（コードで確認）

| 問い                              | 今の答え                                                                                                                                                                                                                                                                                                                                                                   |
|-----------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 他の Mod の UI テキストは訳せるか | **TextMeshPro で出していて、行があれば訳せる**。照合は「表示される英文のハッシュ → 訳」の 1 つの辞書（`TranslationStore`）で、フレームワークの Text ライブラリが TMP の `text` の代入・`SetText(string)`・表示の有効化のたびに引く。誰が出したテキストかは見ていない。**古い uGUI の `Text`、IMGUI（`GUI.Label` など）で自分で描く文字、`SetText` の書式つきの形は対象外** |
| 自動で見つかるか                  | 上と同じ TMP の経路なら、未翻訳の文字列が `_discovered/strings.csv` に自動で記録され、F7 の書き出しにも入る。会話は、F6 が**読み込まれている YarnProject をすべて**書き出すので、Mod が自前の YarnProject を使っていれば入る。Yarn を通さずに TMP へ直接入れる会話は、UI テキストとして拾われる                                                                            |
| Mod が英語を変えたら              | ハッシュが変わり、その行は英語に戻る。台詞 ID（`line:` の行）は Yarn の行 ID が同じなら残る。ゲーム本体向けの「近い英文から探し直す」仕組み（`LineResolution`）は、ゲームの台本だけが対象                                                                                                                                                                                  |
| クラッシュするか                  | 照合は辞書を引くだけで、原理的には起きにくい。**実物の Mod ではまだ試していない**                                                                                                                                                                                                                                                                                          |
| 足りないもの                      | 訳の置き場所が、この Mod の `Translations/` しかない。他の Mod の行を足すには、このリポジトリの `strings.csv` に入れるしかない                                                                                                                                                                                                                                             |

## β版の実験的機能として

他のModのテキストがどう表示されるかは、そのModごとに違い、こちらで全部を試すことはしない。
なので、この機能は**β版の実験的機能**として入れ、使う人が承知の上でオンにする。

- 設定:
  **Options → Mods → Drag'n Wash Localization → Settings** の `[Experimental] Translations from other mods`。
  **既定はオフ**。
  オフの間は、他のModのフォルダーを一切読まない。
- 設定の説明文:

    ```text
    β版・実験的機能。
    ほかのModが同梱した翻訳を読み込みます。
    Modとの組み合わせは未確認で、表示が崩れたり、訳が合わなかったりすることがあります。
    問題があればオフにしてください。
    ```

- オンにしたときは、ログに警告を1回出し、どのModのパックを読んだかを並べる。
- F1 → TranslationとAboutにも「実験的」と出す。
- リリースノートとREADMEでは「β版・実験的機能」の見出しの下に書く。
- 不具合の報告は受けるが、特定のModとの組み合わせを保証はしない。
  Modの作者に頼まれたときだけ、そのModで試す（[確認の計画](#確認の計画)を参照してください）。
- 仕組みが固まり、試したModが増えたら、実験的の表示を外すかを改めて決める。

## 置き場所と形式

```text
BepInEx/plugins/
  DragNWashLocalization/Translations/ko/strings.csv    ← ゲーム本体の訳（このリポジトリ）
  SomeMod/SomeMod.dll
  SomeMod/Translations/ko/strings.csv                  ← SomeMod のテキストの訳（SomeMod が同梱）
  SomeMod/Translations/ja/strings.csv
```

- 列は同じ:
  `key,section,node,order,speaker,translation`（短い `key,speaker,translation` と `key,translation` も可）。
  `key` は英文のSHA-256の先頭16桁で、`tools/hash-strings.ps1 -Path <ファイル>` でそのまま作れる。
- `line:<id>` の行も使える。
- ロケールのフォルダー名は、このModの `Translations/` にあるものと同じにする（`ko`、`zh-Hans` など）。
  このModにない言語は選べないので、その言語のフォルダーだけあっても読まれない。
- `name.txt` は要らない（言語の表示名はこのModが持つ）。
- Mod自身の英文を `source_en` 列に残したファイルも読める。
  このModのリポジトリが守っている「ゲームの英文を配らない」は、ゲームの台本についての約束で、Modの作者が自分で書いた英文は作者のもの。
  ただし**ゲーム本体の英文を含めてはいけない**ことは、作者向けの説明に明記する。

## どのフォルダーを読むか

- BepInExが読み込んだプラグイン（`Chainloader.PluginInfos`）のDLLがあるフォルダーだけ。
  任意のフォルダーは探さない。
- このMod自身のフォルダーは除く。
- 1つのフォルダーに複数のプラグインがあっても、読むのは1回。
- 読むのは起動時と、言語を切り替えたとき。

## 読む順と優先

1. このModの言語パック（ゲーム本体の訳）。
2. 他のModのパック。
   GUIDの順（毎回同じ順になるように）。
3. 翻訳者の作業用コピー（`_discovered/<locale>.working.csv`、開発者ツールがオンのときだけ）。
   今と同じく、すべてに勝つ。

規則：

- **Mod のパックの行は、1の行を置き換えない。**
  同じキーで訳が違えば、1を使い、競合として記録する（訳が同じなら何もしない）。
- 2どうしで同じキーの訳が違えば、先に読んだModの訳を使い、競合として記録する。
- 競合はログに出し、F1 → Translationに一覧を出す。
  Mods画面にも、関わったModごとにお知らせとして出す（「Drag'n Wash Localizationと訳が違う行が3つあります」）。
  そのために、フレームワークにModごとのお知らせ欄を足す（[決めたこと](#決めたこと)を参照してください）。

## 失敗の閉じ込め

- 読めないファイル（壊れたCSV、読み取りエラー、大きすぎるファイル。上限はたとえば5 MB）は、
  **その Mod のそのファイルだけ**読まずに、理由をログに1回出す。
  ほかのModとゲーム本体の訳には影響しない。
- 1つのModから読む行数にも上限を設ける（ゲーム本体の行数の数倍程度）。
- 読み込みはすべて起動時と言語切り替えのときだけで、表示のたびの処理は今と変わらない（辞書を引くだけ）。

## 翻訳者向けのツール

開発者ツールがオンのときだけ（今と同じ）。

- **F1 → Translation**: 読み込んだModのパックを、Mod名・行数・競合の数で一覧にする。
- **ホットリロード**: Modのパックも監視し、保存すると反映する。
- **書き出し**：
  - 会話（F6）の `dialogue_lines.csv` には、もとから `yarn_project` 列があり、ModのYarnProjectの行はその名前でわかる。
    見出しは足さない。
  - UIテキストは、`_discovered/strings.csv` とF7の書き出し（`ui_texts.csv`）に `mod` 列を足し、
    その文字を出したプラグインの名前を入れる。
    開発者ツールがオンのとき、それぞれの文字にはじめて出会ったときに調べる（[決めたこと](#決めたこと)）。
    F7では、それで分からなければ、ラベルとその親のコンポーネントがどのModのものかも見る。空欄は、ゲーム本体か、判別できなかったもの。
- **Hash for commit** は、このModのパック用のまま。
  Modのパックは `tools/hash-strings.ps1 -Path` で作る。
  台本の順に並べる機能はゲーム本体の台本しか知らないので、Modの行は末尾にまとまる。

## Mod の作者向けの手順（案）

1. 自分のModのテキストを英語で、TextMeshProの `text` か `SetText(string)` で出す。
   それだけで翻訳の対象になる（IMGUIや古いuGUIの `Text` は対象外）。
2. 翻訳者に、開発者ツールをオンにしてF7（UI）・F6（会話）で書き出してもらい、
   自分のModの行（UIは `mod` 列、会話は `yarn_project` 列）を選んで `translation` を埋めてもらう。
   会話は台詞ID（`line:<id>` の行）で書くのがオススメ。英文を直しても訳が残る。英文で引く行は、英文を直すと英語に戻る。
3. `tools/hash-strings.ps1 -Path` でハッシュ化し、`Translations/<locale>/strings.csv` としてModと一緒に配る。
4. 機械翻訳などで作った訳は、ファイルの先頭のコメントに `Provisional` と書く（このModの仮翻訳パックと同じ）。
5. クレジットは、そのModのもの。

## 自動翻訳を組み込まない理由

- **通信**: フレームワークは「更新の確認のほかは何も送らない」と説明している。実行時の機械翻訳は、プレイ中のテキストを外部に送ることになる。
- **鍵と費用**: 誰のAPIキーで、誰が払うのかが決まらない。このModが鍵を扱うことはしない。
- **内容**: Modには成人向けの内容もあり、翻訳サービスの利用規約に触れうる。
- **品質と責任**: 誤訳が、このModの名前で表示される。
- **範囲**:「全部を抱えない」。訳を作る手段は、Modの作者と翻訳者が選べばよい。

## フレームワークとの分担

最初はLocalizationの中で、フォルダーの置き方の約束事として作る。
フレームワークにAPIは足さない。
別の翻訳Modが出てきて、同じ約束事を共有したくなったら、フォルダーの発見と競合の記録をフレームワークのTextライブラリに移す。

## 決めたこと

2026-09-17に決定。

- **競合はMods画面にも出す。**
  先にフレームワークに小さな「Modごとのお知らせ欄」を足す（フレームワークのロードマップにある項目。
  `GameHooks.Unavailable` は「機能が使えない」の意味なので流用しない）。
  そのうえでLocalizationが、競合に関わったModの下にお知らせを出す。
  お知らせ欄のない古いフレームワークでは、ログとF1にだけ出す。
- **UIテキストがどのModのものかは、記録するときだけ調べる。**
  開発者ツールがオンで、未翻訳の文字をはじめて記録するときに、呼び出し履歴を1回たどって
  最初のプラグインのアセンブリを探し（フレームワークの接続の見張りと同じやり方）、そのModを `mod` 列に入れる。
  表示の処理は遅くならず、開発者ツールがオフなら何も調べない。
- **Modの台詞に `LineResolution` は効かせない。**
  Modごとの台本の順序データが要るため。
  代わりにModの台詞は台詞IDで書いてもらう（`line:<id>` の行は英文が変わっても残る）。
  作者向けの手順にそう書く。
  英文で引く行は、英文が変わると英語に戻る。
- **この Mod にない言語は読まない。**
  言語の一覧・表示名・フォントは、このModが持つ。
  そういう言語のフォルダーは、ログに1行出して読み飛ばす。
  言語を増やすときは、先にこのリポジトリにパックを足す。

## 確認の計画

- 他のModをこちらから進んで試すことはしない。
  Modの作者から「自分のModで翻訳が効くか確かめてほしい」と頼まれたときに、そのModで試す。
  見るのは、「UIテキストが `_discovered/strings.csv` に出るか」「会話がF6で出るか」「訳の行を足すと表示が変わるか」「クラッシュしないか」。
- 試した結果は、この設計の「今の答え」の表に反映する。
- 実装は `experimental/` ブランチで。
  テスト用に、テキストを出すだけの小さなModをこちらで作る。
